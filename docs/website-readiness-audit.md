**Purpose:** distinguish what is tested from what is merely implemented, and identify safe next steps before claiming every live flow is ready.

## Executive finding

The repository has broad application code and good automated coverage, but the available evidence does **not** justify saying every production workflow is “100% workable.” The ordinary browser suite is explicitly built in demo mode without a database: 64 tests pass and 47 credential-dependent cases skip. A separate isolated workflow proves the QR-throttle path against disposable PostgreSQL/PostgREST, and its four PostgreSQL throttle regression cases pass. Other real-service flows remain unverified. The current clean install and full `npm audit` report zero vulnerabilities after a compatible `minimatch` override; the CI actions and runner images have also been updated, pending hosted verification of those workflow edits.

The original six approved application follow-ups are implemented where safe: production fails closed on missing Supabase public config; local demo is explicit; CI has a separate test-only opt-in; canonical operator docs are tracked; disposable DB/browser coverage runs only against synthetic local services; and `/api/health` now returns only allowlisted SQLSTATE/PostgREST diagnostic codes. Toolchain/audit maintenance is the latest verified follow-up. The first pushed run exposed that `NODE_ENV` is replaced at test-build time and that shared Supabase env code must not enforce server-only policy in the browser. Both were fixed in `95957c7`. The PR #88 retry behavior was already present; its missing health diagnostic was ported with stricter output validation in `8046ee3`. CI and both browser workflows pass on that commit. PR #88 was conflicting, so after porting its behavior it was closed as superseded rather than merged. Schema-fidelity comparison remains blocked: Supabase denied restoration of the inactive non-production project, reports no active services, and timed out listing its migration history. The user's GST decision is Option A: preserve the existing explicit configured-rate path, with no tax-policy expansion. This is not legal/adviser approval.

No production integration test, production-data read, order, payment, migration, or deployment change has been performed for these follow-ups. Production remains out of bounds for testing.
