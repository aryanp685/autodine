## Executive finding

The repository has broad application code and good automated coverage, but the available evidence does **not** justify saying every production workflow is “100% workable.” The ordinary browser suite is explicitly built in demo mode without a database: 64 tests pass and 47 credential-dependent cases skip. A separate isolated workflow proves the QR-throttle path against disposable PostgreSQL/PostgREST and now also exercises a persisted guest-order → kitchen → cashier → close/receipt database lifecycle; its four DB regression cases pass. Other real-service flows remain unverified. The current clean install and full `npm audit` report zero vulnerabilities after a compatible `minimatch` override; the updated CI actions and runner images have passed hosted CI and browser workflows.

The original six approved application follow-ups are implemented where safe: production fails closed on missing Supabase public config; local demo is explicit; CI has a separate test-only opt-in; canonical operator docs are tracked; disposable DB/browser coverage runs only against synthetic local services; and `/api/health` now returns only allowlisted SQLSTATE/PostgREST diagnostic codes. Toolchain/audit maintenance is the latest verified follow-up. The first pushed run exposed that `NODE_ENV` is replaced at test-build time and that shared Supabase env code must not enforce server-only policy in the browser. Both were fixed in `95957c7`. The PR #88 retry behavior was already present; its missing health diagnostic was ported with stricter output validation in `8046ee3`. CI and both browser workflows pass on that commit. PR #88 was conflicting, so after porting its behavior it was closed as superseded rather than merged. Schema-fidelity comparison remains blocked: Supabase denied restoration of the inactive non-production project, reports no active services, and timed out listing its migration history. The user's GST decision is Option A: preserve the existing explicit configured-rate path, with no tax-policy expansion. This is not legal/adviser approval.

No production integration test, production-data read, order, payment, migration, or deployment change has been performed for these follow-ups. Production remains out of bounds for testing.

## What remains (prioritized)

1. **P0 — authorized non-production schema comparison and smoke test (blocked).** The only AutoDine non-production Supabase project is inactive. The connected Supabase app denied restore with HTTP 403, reported no active services, and timed out listing migrations. There is no active non-production branch. To finish this gate, the organization owner must grant the connected account permission to restore/use that project or provide an active disposable non-production project. Then compare migration history, schema objects, functions, grants, RLS, and indexes against the repository and run smoke checks there. Production is not a substitute.
2. **P1 — full authenticated real-DB browser journey (partially covered).** The disposable harness now exercises guest order persistence → kitchen state transition → cashier settlement → atomic session close and receipt issuance/retry against real PostgreSQL, and that run passed. It does not yet drive staff-authenticated screens/browser interactions through PostgREST; that remains a coverage gap rather than something proved by the demo browser suite.
3. **P1 — authenticated account lifecycle E2E (environment-gated).** Run signup/invitation, confirmation, login, reset/recovery, role access, and multi-tenant isolation against an approved non-production app/account. The 47 skipped browser cases require that safe endpoint and credentials; do not point them at production.
4. **P2 — tooling maintenance (resolved).** Added a compatible `minimatch@11.0.1` override, updated workflow actions to checkout@v7/setup-node@v7/upload-artifact@v7, and pinned Ubuntu runners to `ubuntu-24.04`. Clean `npm ci`, full audit (zero vulnerabilities), typecheck, lint, tests, build, CI, hermetic browser E2E, and isolated PostgreSQL browser E2E all pass on `fa2f478`.
5. **P2 — external/runtime evidence.** Real email delivery, AI provider calls, OS/browser printer behavior, and physical printer output are not covered by unit tests. Test providers only in sandbox accounts; browser/OS printing is the supported model and printer-device integration is out of scope.
6. **P2 — legal/product decisions.** GST stays frozen under Option A until tax-adviser rules exist. Online payments/subscriptions remain unavailable/out of scope; no gateway implementation is a readiness blocker unless product scope changes.
7. **Release delivery — not in `main`.** The changes are verified on the active Arena branch, but there is no open PR from this branch and no deployment. The next release action is a reviewed PR/merge through the repository's normal process; no production deployment was requested or performed.

Hosted CI [42407347822](https://github.com/aryanp685/autodine/actions/runs/42407347822), hermetic browser E2E [42407347831](https://github.com/aryanp685/autodine/actions/runs/42407347831), and isolated PostgreSQL/PostgREST browser E2E [42407347812](https://github.com/aryanp685/autodine/actions/runs/42407347812) passed on `2ab8964`.
