## Changes

- Upload refuses a missing/mismatched manifest or an artifact without the encrypted backup framing. The scheduled pipeline independently decrypts and verifies the artifact before upload. HTTPS endpoint overrides are limited to official Backblaze S3 endpoints with matching region; redirects are refused.
- B2 download retries transient read failures (including interruption while consuming the body), requires matching object metadata and manifest, checks pagination, and publishes only complete local files without overwriting an existing pair. Synthetic fetch tests do not contact B2.
- Custom-format pg_dump uses a private temporary plaintext file and removes it on ordinary success or failure. A forced pg_dump failure tests this cleanup. An uncatchable termination may leave plaintext on disk; the workflow also removes its runner directory in an unconditional cleanup step.
- The new `Staging B2 backup and disposable restore` workflow is manual-only, uses uniquely named `backup-staging` Environment secrets and matching staging project/bucket variables, rejects Production and pooler/host overrides, and does not prune. It uploads staging data and can create charges; it has **not** been dispatched. The workflow must be reviewed and integrated before normal default-branch dispatch.
- The owner checklist now distinguishes the daily 24-hour RPO *target* from a guarantee, explains missing-run and optional-alert limitations, and warns that B2 name-only deletes create markers rather than reclaiming previous versions. Local retention and remote visible recovery-point selection do not prove physical reclamation.
